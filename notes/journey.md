# 这次是怎么认出来的

目标很窄：第 6 天，边境城镇里亚马，前期打得疼。先动数字，主要是等级，金币顺手改。不拆剧情脚本。

## 先看游戏自己的加载，不套旧改档器

磁盘上的 `AGE.EXE` 代码段是加壳的，熵到顶，入口在别的区段里。进程跑起来之后代码是解开的。字符串、解密和 LZSS 都在这块活的映像里，不在磁盘文件里。

存档不在「文档」。文档被 OneDrive 指走了。活的存档在 `%LOCALAPPDATA%\Eushully\EU-022_ZHCN\SAVE`。菜单上的 SAVE 004 是文件 `SAVE04.DAT`，格式串是 `%s\SAVE%2.2d.DAT`。Steam 云目录里只有旧截图，没有第二份存档。

加载函数读出文件头之后的五个整数，按上一篇的除法异或解开，再 LZSS。两个校验和都对上了，包括原来的档和后来重新打包的档。

有一版图省事，把「未压缩」那条捷径打开，文件涨到大约 12 MB。读档进到脚本 `SAVE.BIN` 时，LZSS 往窗口外写，直接访问违例。之后只走真的 LZSS，压回去仍是 1.5 MB 上下。

## 第一次改错了数

钱包比较好认。三份早期存档里，只有下标 `9873` 从 0 变成 180，再保持 180。把它和另一份同样的 180 一起改成 300000。

等级当时看走眼。角色行第二项是 21，就把它当成等级改成 40，HP 和攻击也按比例放大。装备页打开之后，画面上仍是 HP 581、SP 21、物攻 72。21 是体力。打开角色页时，游戏用基础数据把整行面板重算了一遍，改过的数被盖回去。

紧挨着的 `21, 32, 23` 是三个人的体力，不是三个人的等级。文件头里那个单独的 4 也不是等级：别的档同一位置是 16 或 37，面板还是这一套早期体力。

中间还去点过游戏窗口，想打开「能力」页看等级旁边的数。点偏了，又去跟鼠标坐标。这条路放下了。存档里的数够用，不必靠点界面。

## 4 和 1 把等级表钉死

画面上马克是 4 级，苏菲亚是 1 级。整份解开的存档里，整数 4 只有二十来个。其中一段是：

```
1246717:  4, 1, 4, 0, 0, 0, ...
```

更早的 SAVE00 同一位置是 `3, 0, 3`。苏菲亚还没入队，马克和瑞理一起从 3 升到了 4。角色顺序就是马克、苏菲亚、瑞理，和入队等级一致：两人 3 级入队，苏菲亚 1 级入队。

这一段在运行中的变量数组里也是 `4, 1, 4`，下标 `1240852`。把它写成 40 之后，角色页上就是 40。再写成 98 也留住了。经验那一页没动。装备在别的数组里，武器还在。

金币一直在 `9873`。编队和装备页不画钱，槽位缩略图又是二月的旧图，所以数字改完不会立刻出现在这两个地方。商店和持有品读的是这个钱包。

## 留在脚本里的，和没留的

`tools/age_save.py` 是解密、加密、LZSS 和两套校验和。`tools/edit_slot.py` 只改钱包和前三个等级，周围的数对不上就拒绝写。

没有放进来的：游戏本体、补丁、存档、解开的明文、某一次启动的进程号和那一次的内存密钥。密钥在引擎对象 `+0x716BC`，下次启动会变。
